## 4. 부호화와 발전 (데이터 직렬화) ✅

---

### 💬 상위, 하위 호환성
- **배경**: rolling update 등으로 과거 코드와 현재 코드 공존 가능
- **하위 호환성**: 새로운 코드가 과거 코드가 기록한 데이터를 읽을 수 있어야 함
- **상위 호환성**: 과거 코드가 새로운 코드가 기록한 데이터를 읽을 수 있어야 함

---

### 💬 데이터 구조

#### 1️⃣ 메모리 데이터 (CPU 접근 용이)
- **컴파일 타임**
    - 자바 코드 → 바이트코드
    - 바이트코드에 변수별 슬롯 할당 (local variable table)
    - 심볼릭 참조 정의 (Fieldref, Methodref 등)
- **런타임**
    - **스택 프레임 단위 저장**
        - 슬롯: primitive 값 또는 객체 참조
        - 객체 참조: 힙 객체 가리키는 가상주소
    - **힙 영역**
        - 객체 실제 데이터 저장
    - **접근 과정**
        - 스택 → 슬롯 → 객체 참조 → 힙 객체
        - 필요시 OS/CPU 레벨에서 가상주소 → 물리주소 변환

#### 2️⃣ 파일/네트워크 데이터 (바이트열 직렬화)
- **텍스트 형식**: JSON, XML, CSV
- **이진화**: 텍스트 데이터를 바이너리 형태로 축약
    - JSON: MessagePack, BSON, BJSON, UBJSON, BISON
    - XML: WBXML, Fast Infoset
- **스키마 정의 & 이진 직렬화**
    1. 통신 스키마 미리 정의
    2. 코드 단에서 스키마 기반 자동 구현체 생성
    3. 이진화 방식으로 통신

   - Thrift
     - **스키마**
       ```
       struct Person {
       1: required string userName;
       2: optional i64 favoriteNumber;
       3: optional list<string> intrests;
       }
       ```
     - **바이너리/컴팩트 프로토콜 지원**

    - Protocol Buffers (Protobuf)
      - **스키마**
        ```
        message Person {
        required string user_name = 1;
        optional int64 favorite_number =2;
        repeated string interests = 3;
        }
        ```
      - **바이너리 프로토콜 지원**

    - Apache Avro
      - **스키마 (IDL)**
        ```
        record Person {
        string userName;
        union { null, long } favoriteNumber = null;
        array<string> interests;
        }
        ```
      - **스키마 (JSON)**
        ```
        {
        "type": "record",
        "name": "Person",
        "fields": [
        {"name": "userName", "type":"string"},
        {"name": "favoriteNumber", "type": ["null", "string"], "default": null},
        {"name": "interests", "type": {"type": "array", "items": "string"} }
        ]
        }
        ```
      - **특징**
          - 필드 순서나 구분값 없음
          - 서버 읽기 스키마, 클라이언트 쓰기 스키마로 상·하위 호환성 보장
          - optional 값 없으면 default 값 사용
          - 동적 스키마 생성 가능 → 유연성 확보
          - 핵심: 상하위 호환성 보장

### 💬 데이터 플로우

#### 1️⃣ 데이터베이스
- 프로세스 A가 직렬화 데이터 기록 → 프로세스 B가 역직렬화하여 읽음

#### 2️⃣ 서비스 (REST, SOAP, RPC)
- 네트워크를 통해 요청 전송 후 즉시 응답

#### 3️⃣ 메시지 (비동기)
- **메시지 브로커**
    - 프로세스 A가 큐/토픽으로 메시지 전송 (RabbitMQ, Kafka)
    - 프로세스 B가 큐/토픽에서 메시지 수신
- **분산 액터 프레임워크**
    - **액터 모델**: 단일 프로세스 내 동시성, 액터는 상태와 메일박스 보유, 비동기 메시지 송수신
    - **분산 액터 모델**: 여러 노드 확장, jvm 단위 분산 처리, 메시지 브로커 내재, 네트워크/로컬 구분 불필요

#### 4️⃣ 분산 액터 프레임워크 그림 요약
```
──────────────────────────────────────────────
🌐  분산 액터 프레임워크
──────────────────────────────────────────────
(예: Akka Cluster)
──────────────────────────────────────────────

                   ┌────────────────────┐
                   │   Cluster (전체 시스템) │
                   └──────────┬─────────┘
                              │
              ┌───────────────┼────────────────┐
              │               │                │
      ┌────────────┐   ┌────────────┐   ┌────────────┐
      │   Node #1  │   │   Node #2  │   │   Node #3  │
      └──────┬─────┘   └──────┬─────┘   └──────┬─────┘
             │                 │                 │
      ┌──────▼──────┐    ┌─────▼──────┐    ┌─────▼──────┐
      │  ActorSystem│    │ ActorSystem│    │ ActorSystem│
      └──────┬──────┘    └─────┬──────┘    └─────┬──────┘
             │                 │                 │
      ┌──────▼──────┐    ┌─────▼──────┐    ┌─────▼──────┐
      │  Supervisor │    │ Supervisor │    │ Supervisor │
      │ (계층 루트) │    │ (복구 담당) │    │ (에러 처리) │
      └──────┬──────┘    └─────┬──────┘    └─────┬──────┘
             │                 │                 │
    ┌────────▼────────┐ ┌──────▼───────┐ ┌──────▼───────┐
    │   Actor (A)     │ │   Actor (B)  │ │   Actor (C)  │
    │  상태(State)    │ │  상태(State) │ │  상태(State) │
    │  메일박스(MBox) │ │  메일박스    │ │  메일박스    │
    └────────┬────────┘ └──────┬───────┘ └──────┬───────┘
             │                 │                 │
             ▼                 ▼                 ▼
    ┌────────────────────────────────────────────┐
    │          💬 Message Passing                │
    │  Actor 간 직접 접근 X                        │
    │  오직 메시지로 상호작용 (비동기)             │
    │  Mailbox 단일 소비자 모델 → Thread-safe      │
    │  Lock, synchronized 불필요                   │
    └────────────────────────────────────────────┘

──────────────────────────────────────────────
⚙️ 핵심 철학 (Akka / Actor 모델)
──────────────────────────────────────────────
1️⃣ 공유 메모리 대신 메시지 전달로 동시성 제어
2️⃣ 각 Actor는 독립된 상태(State)를 가짐
3️⃣ 스레드 안전이 모델 자체로 보장됨
4️⃣ 장애는 “let it crash” — Supervisor가 복구
5️⃣ 클러스터 간 Actor 메시지 라우팅으로 분산처리
──────────────────────────────────────────────

예시 흐름:
┌────────────────────────────────────────────────┐
│  Client 요청 → Node#1의 ActorA 수신            │
│    │                                           │
│    ▼                                           │
│  ActorA ──▶ (Message) ──▶ Remote ActorB(Node#2)│
│    │                                           │
│    ▼                                           │
│  ActorB 응답 메시지 ─▶ ActorA                     │
└────────────────────────────────────────────────┘
비동기, Non-blocking, Lock-free 분산 실행 모델
```

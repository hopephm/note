

## 1. 신뢰할 수 있고 확장 가능하며, 유지보수 하기 쉬운 어플리케이션 ✅

---

### 💬 데이터 구성 표준 요소

| 데이터 구성 요소           | 예시                                | 설명                                                                                   |
|---------------------------|------------------------------------|--------------------------------------------------------------------------------------|
| 데이터베이스 (DB)         | MySQL, Oracle, MongoDB             | 구조화된 데이터를 저장하고 관리하는 시스템                                              |
| 캐시 (cache)              | Radis, MemCached                    | 자주 접근하는 데이터를 메모리에 저장하여 빠른 읽기/쓰기 제공                             |
| 검색 색인 (search index)   | ElasticSearch, Solr                 | 데이터를 검색 효율 위주로 저장하고, 인덱스를 통해 빠르게 조회                             |
| 스트림 처리 (stream processing) | Kafka, RabbitMQ, SQS            | 실시간 데이터 처리 및 메시지 전송                                                     |
| 일괄 처리 (batch processing)   | Hadoop, Spark                    | 통계, 분석, 집계 등 대규모 데이터 배치 처리                                           |
💡 **ElasticSearch**
- 도큐먼트 기반 저장소, 트랜잭션 및 ACID 보다는 검색 효율 위주
- 저장되는 모든 도큐먼트에 따라 역인덱스를 생성해두고, 샤드 기반으로 접근하여 병렬처리

### 💬 데이터 시스템의 변화
- 더 이상 전통적인 구분에 맞지 않고 **경계가 흐려짐**
  - 레디스: 캐시라고 생각하지만, 영속성 있는 메시지 큐처럼 쓸 수 있음
  - 카프카: 메시지 큐라고 생각하지만, 이벤트 영속성 보장
- 단일 도구로 처리되던게 **규모에 따라 분리**됨
  - DB를 쓰며 데이터 처리는 엘라스틱서치나 솔라를 활용함

### 💬 용어 사전

#### 1️⃣ 신뢰성 (Reliability)
- **정의**: 올바르게 동작하며 예상치 못한 부분도 전반적인 정상 플로우를 따름
- **관련 용어**
    - **결함 (Fault)**: 사양에서 벗어난 케이스
    - **내결함성 / 탄력성 (Fault-tolerance / Resilience)**: 결함에 대처되는 정도 → 사양이 아님에도 정상 플로우로 돌아옴
    - **장애 (Failure)**: 사양에 벗어나는 동작으로 전체 시스템이나 정상 플로우에 영향 발생

#### 2️⃣ 확장성 (Scalability)
- **정의**: 증가한 부하에 대처하는 시스템 능력
- **부하 기술 (Load Engineering)**
    - **부하**: 시스템에 가해지는 작업량
    - **부하 매개변수**: 부하를 발생시키는 요인 → 해당 값 정의가 중요
        - 예시: 초당 요청수, DB read/write 비율, 캐시 적중율, 동시 활성 사용자 등
- **성능 기술 (Performance Engineering)**
    - **성능**
        - **처리량 (Throughput)**: 초당 처리할 수 있는 작업량
        - **응답 시간 (Response Time)**: 하나의 작업이 처리되는 시간
    - **분포**
        - 성능은 분포로 접근 필요
        - 특이 값 처리: 상위 n% 지연율
    - **중앙값**
        - P50: 100개 중 50번째 값 → 하위 50개는 이보다 작은 처리속도, 상위 50개는 이보다 빠른 처리속도
        - P95, P99, P999 등 사용 가능
- **부하 대응**
    - **스케일 업 (Scale-up)**: 용량 확장 → 고성능 장비로 전환
    - **스케일 아웃 (Scale-out)**: 규모 확장 → 저성능 장비를 추가

#### 3️⃣ 유지보수성 (Maintainability)
- **정의**: 지속 가능하게 유지하기 용이한 정도
- **관련 특성**
    - **운용성 (Operability)**: 운영자가 운영하기 편리한 정도 → 자동화, 반복 태스크 제거
    - **단순성 (Simplicity)**: 사이드 이펙트 방지를 위한 올바른 추상화
    - **발전성 (Evolvability)**: 요구사항 변경 시 수정하기 쉬운 정도
        - == 유연성 (Extensibility), == 수정 가능성 (Modifiability), == 적응성 (Plasticity)
        - feat. TDD, 리팩토링

### 🏖️ 개요

---

- 세션 설명

```markdown
어드민스튜디오는 웹 프런트개발자 없이 손쉽게 어드민 서비스를 만들 수 있는 노코드 웹앱 에디터 입니다.

웹앱 에디터라는 복잡한 서비스를 구축하며 마주한 다양한 문제와 해결 과정을 공유합니다.
 
Definition-to-Component 해석기, 인터랙티브 캔버스 레이어, 전역 데이터 관리, 스펙이 다양한 API의 손쉬운 연동, 임시 저장과 미리 보기, 그리고 배포 인프라까지. 복잡성을 넘나들며 쌓은 실전 설계 인사이트를 나눕니다.
```

- 키워드

```markdown
- 에디터 서비스를 개발하는 개발자
- '노코드' 프로덕트에 관심이 있는 분
- 복잡한 프론트엔드 프로젝트의 설계에 대해 고민이 있는 개발자
- 프론트엔드와 백엔드를 넘나드는 풀스택 개발을 지향하는 분
```

### 🗒️ 노트

---
#### 1️⃣ 개요

- 정의 : 어드민 프론트엔드 제작을 위한 웹 에디터 서비스
- 목표
  - 비개발자도 간편하게 표준화된 어드민을 제작하는 웹 에디터
  - 어드민: 대고객 서비스에 비해 완성도 보다 빠른 속도가 중요함

#### 2️⃣ 아키텍쳐

- 어플리케이션 레벨
  - 에디터: 서비스 기능, 페이지 화면, 구성요소 등을 편집하여, 저장, 공유, 배포
  - 서버: 에디터에서 편집한 데이터를 저장, 배포 이력 관리
  - 뷰어: 제작된 서비스를 사용자에게 제겅
- 모듈 레벨
  - foundation layer
    - types: 타입, 인터페이스, 도메인 모델 정의
    - toolkit: 공통 유틸리티
  - feature layer
    - editor-core: 편집 기능
    - block-renderer: 정의를 기반으로 컴포넌트 렌더링
    - components: ui 컴포넌트, 속성
  - platform layer
    - editor-platform: 에디터 구성 모듈 통합
    - viewer-platform: 뷰어 구성 모듈 통합
  - application layer
    - apps/editor: 에디터 앱 편집 인터페이스
    - apps/viewer: 어드민 동작 인터페이스

#### 3️⃣ 기능

- 컴포넌트 정의 및 해석: json 기반 dsl을 정의
  - id, types, props 등이 필드로 객체 형태 표현
  - api 호출 - 이벤트 핸들러 - ui 컴포넌트 렌더링의 과정도 dsl로 표현
- 상호작용 영역 구성
  - 뷰어와 에디터의 코드를 완전 분리하되, 에디터에서도 미리보기 기능은 필요하므로 계층 형태로 레이어 구분
  - 렌더링 레이어와 인터렉션 레이어를 구분 / 두 레이어간 위치 정보를 저장하는 캐시스토어에 wrapper로 컴포넌트를 감싸 렌더링
  - 상호작용시 wrapper를 통해 블록 위치 검사
- 컴포넌트 수정
  - event bus 패턴으로 직접 참조 배제
  - 에디터에서의 상호작용을 eventBus에 넘기고 eventBus에서 구독하는 컴포넌트에 상호작용 작업 수행
- API 연동
  - 각기 다른 API 서버에 대해 Open API Specification을 따르는 표준화 형식에 대해서만 지원
  - 구조
    - API layer: API List fetcher, API Request Precessor
    - Processing layer: format parser, schema validator
    - Conversion layer: Dsl Converter, Reverse Converter
    - Input layer: Dsl render, API Test
- 저장하기
  - data manager: 모든 상태를 하나의 스토어에서 관리 
  - 임시저장: Indexed DB / 페이지 이탈 안정성 보장
  - 서버: 영구저장 / 프로젝트 버저닝
- 배포하기
  - 버전 리스트 조회
  - 버전 선택 후 배포 요청 - published DB 테이블에 최신 버전 저장
  - 단일 뷰어에 alternative 도메인을 적용해 여러 어드민 서비스

### ⏰ 후기

---

- json으로 dsl을 정의해 서비스에 활용하는 개념
- wrapper를 통해 서로 다른 레이어/모듈 간 호환성 보장 개념
- eventBus를 통한 의존성 분리 개념
- DB를 활용한 서비스 버전관리 개념
